## Bug and minimal migration change

Legacy archived Daily Sales rows may contain compatibility `branchId` values that are not proof of a real branch. The Version 54 candidate previously allowed every positive `daily_sales_summaries.branchId` to participate in canonical Branch discovery, including archived rows created from historical compatibility data.

Before:

```sql
SELECT branchId AS id
FROM daily_sales_summaries
WHERE branchId > 0
```

After:

```sql
SELECT DISTINCT branchId AS id
FROM daily_sales_summaries
WHERE branchId > 0
  AND isLegacyArchive = 0
```

The rule is source-based. There is **no** `branchId != 1`, `branchId == 1`, or other Branch-ID special case. A real non-legacy Branch 1 remains valid evidence. Other existing numeric Branch sources in `MIGRATION_53_54` remain unchanged, so a deterministic real Branch 1 from another valid source can still be preserved.

The archived Daily Sales rows themselves are not deleted or rewritten by this fix. The existing non-destructive table rebuild that removes the historical `DEFAULT 1` remains unchanged and preserves row contents.
