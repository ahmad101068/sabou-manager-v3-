# Current Canonical Architecture

This document describes the production architecture at the pre-Phase-3 freeze. Historical migrations are compatibility infrastructure, not alternative runtime architecture.

## Layer direction

The effective dependency direction is **UI → application/service contracts → domain → repository contracts → data/Room**. Domain code must not depend on Compose, and data code must not expose UI state types as domain contracts. Some mature modules combine application orchestration and repository implementation in `data/repository`; this is documented rather than rewritten before the runtime test safety net.

## Branch identity audit

`branchId` is the canonical identity. `branchName`, `branch`, `branchLabel`, and legacy branch strings are display/snapshot/search/compatibility metadata only. `CanonicalBranchResolver` always returns a canonical `BranchEntity`; numeric `branchId` is preferred, while deterministic text lookup is retained solely as a compatibility adapter for pre-canonical records and existing legacy-form DTOs. No downstream accounting, payroll, receivable, inventory, or Daily Sales posting may treat the text itself as the persisted branch identity. New code must supply `branchId` directly.

Room v55 adds `branch_legacy_aliases` as a compatibility read model for historical/reporting tables that still expose `branchName`/`branch`. Dashboard selection remains numeric `branchId`; the DAO resolves only deterministic aliases belonging to exactly one Branch and never converts the selected ID back to the current display name. Rename records the old and new display names as aliases without rewriting historical sales/accounting rows. Ambiguous legacy aliases are intentionally excluded from branch-specific attribution while remaining visible in organization-wide reads. This is not a contract for new writes and must not be copied into new business logic.

## Financial semantic invariants

- Net Sales = Gross − Discounts − Returns.
- Revenue = Net Sales + Service Revenue.
- Tax is not revenue.
- Amount To Settle = Revenue + Tax.
- Gross Profit = Revenue − COGS.
- Collection of an old receivable is not new revenue.
- Actual Food Cost requires actual evidence; unavailable actual is reported as unavailable.
